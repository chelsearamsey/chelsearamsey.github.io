Build a Cat Breed Lookup CLI with Python and TheCatAPI

In this tutorial, you'll build a Python command-line interface (CLI) application that retrieves cat breed information from TheCatAPI.

The application prompts users to enter a cat breed and retrieves its origin, life span, temperament, and description. Users can perform multiple searches without restarting the application.

Along the way, you'll learn how to authenticate REST API requests, pass query parameters, parse JSON responses, and handle common request failures.

Prerequisites

To follow this tutorial, you'll need:

  • Python 3 installed on your computer
  • An API key from TheCatAPI
  • Basic familiarity with Python and the command line

1. Set up the project

Create a new Python project and install the required dependencies:

pip install requests python-dotenv

The application uses two third-party packages:

  • requests handles HTTP requests to TheCatAPI.
  • python-dotenv loads configuration values from a .env file into the application's environment.

Storing the API key outside the source code prevents it from being exposed when the application is published to a Git repository.

Configure the API key

Create a file named .env in your project directory.

Add your API key using the following format:

CAT_API_KEY=your_api_key_here

Replace your_api_key_here with your actual API key.

Protect the API key

Create a .gitignore file in the project directory and add: 

.env

This instructs Git to ignore the .env file, preventing it from being accidentally committed to the repository.

Important: If an API key has already been committed, adding .env to .gitignore will not remove it from Git history. The exposed key should be revoked or rotated.

For developers who clone your project, you can also provide an .env.example file: 

CAT_API_KEY=your_api_key_here

Unlike .env, this example file can safely be committed because it contains no credentials.

2. Load the API key

Import os and load_dotenv, then load the environment variables: 

import os

import requests
from dotenv import load_dotenv

load_dotenv()
api_key = os.getenv("CAT_API_KEY")

load_dotenv() reads the values defined in the .env file and makes them available as environment variables for the running application.

os.getenv("CAT_API_KEY") retrieves the API key from the environment and stores it in api_key.

3. Authenticate the request

TheCatAPI accepts the API key through the x-api-key request header. Create a dictionary containing the header: 

headers = {
    "x-api-key": api_key
}

Passing the API key in the request header allows TheCatAPI to authenticate the request without including the credential in the URL.

4. Prepare the API request

Prompt the user to enter a cat breed:

breed = input("Enter a cat breed: ")

Define the API endpoint and query parameter:

url = "https://api.thecatapi.com/v1/breeds/search"

params = {
    "q": breed
}

The q parameter contains the breed name entered by the user. When the request is sent, requests encodes the parameters into the URL query string.

5. Send the HTTP request

Send a GET request to the API using the endpoint, authentication header, and query parameters: 

response = requests.get(
    url,
    headers=headers,
    params=params,
    timeout=10
)

The headers argument includes the API key created earlier, while params supplies the breed search parameter.

Setting timeout=10 prevents the application from waiting indefinitely if the API does not respond.

6. Handle request failures

Network problems, timeouts, and other connection errors can prevent the application from receiving a response. Wrap the request in a try/except block: 

try:
    response = requests.get(
        url,
        headers=headers,
        params=params,
        timeout=10
    )
except requests.exceptions.RequestException:
    print("The API could not be reached. Please check your internet connection.")
    continue

RequestException catches errors that occur while attempting to make the request. If the request fails, continue returns the application to the beginning of the search loop.

7. Handle HTTP response errors

A successful HTTP request does not necessarily mean the API returned a successful response. Check the response status code before processing the returned data: 

if response.status_code == 200:
    breed_info = response.json()
else:
    print(f"API request failed. Status code: {response.status_code}")

The application processes the response body only when TheCatAPI returns 200 OK. Other status codes are reported to the user instead.

8. Parse the JSON response

For a successful request, convert the JSON response into Python data: 

breed_info = response.json()

The breed search endpoint returns a JSON array. After parsing, breed_info is a Python list containing dictionaries that represent matching breeds.

9. Handle searches with no results

Before accessing a result, verify that the API returned at least one matching breed: 

if breed_info:
    cat = breed_info[0]
else:
    print(f"No matching breed found for '{breed}'.")

Checking the list before accessing breed_info[0] prevents an IndexError when the API returns an empty array.

When results are available, breed_info[0] selects the first matching breed returned by the API.

10. Display the breed information

Use the first returned breed to display the fields relevant to the user: 

cat = breed_info[0]

print(f"Name: {cat['name']}")
print(f"Origin: {cat['origin']}")
print(f"Life Span: {cat['life_span']} years")
print(f"Temperament: {cat['temperament']}")
print(f"Description: {cat['description']}")

Each value is retrieved from the breed object using the corresponding JSON property name returned by TheCatAPI.

11. Allow multiple searches

Wrap the application in a loop so users can search for additional breeds without restarting the program: 

while True:
    breed = input("Enter a cat breed: ")

    # Send and process the API request.

    while True:
        search_again = input("Search for another breed? (y/n): ").strip().lower()

        if search_again == "y" or search_again == "n":
            break
        else:
            print("Please enter a valid input.")

    if search_again == "n":
        break

The inner loop validates the user's response before allowing the application to continue. Using strip() and lower() normalizes the input so values such as Y and y are accepted.

12. Complete application

The complete application combines authentication, query parameters, response handling, and repeated searches: 

import os

import requests
from dotenv import load_dotenv

load_dotenv()
api_key = os.getenv("CAT_API_KEY")

headers = {
    "x-api-key": api_key
}

while True:
    breed = input("Enter a cat breed: ")

    url = "https://api.thecatapi.com/v1/breeds/search"

    params = {
        "q": breed
    }

    try:
        response = requests.get(
            url,
            headers=headers,
            params=params,
            timeout=10
        )
    except requests.exceptions.RequestException:
        print("The API could not be reached. Please check your internet connection.")
        continue

    if response.status_code == 200:
        breed_info = response.json()

        if breed_info:
            cat = breed_info[0]

            print(f"Name: {cat['name']}")
            print(f"Origin: {cat['origin']}")
            print(f"Life Span: {cat['life_span']} years")
            print(f"Temperament: {cat['temperament']}")
            print(f"Description: {cat['description']}")
        else:
            print(f"No matching breed found for '{breed}'.")
    else:
        print(f"API request failed. Status code: {response.status_code}")

    while True:
        search_again = input("Search for another breed? (y/n): ").strip().lower()

        if search_again == "y" or search_again == "n":
            break
        else:
            print("Please enter a valid input.")

    if search_again == "n":
        break

Run the application

Run the application from the project directory:

python main.py

Enter a breed name when prompted. After displaying the result, the application asks whether you want to perform another search.

Project files

Your completed project should contain the following files:

cat-breed-lookup/
├── .env
├── .env.example
├── .gitignore
├── README.md

The .env file remains local and should not be committed to the repository. The .env.example file documents the configuration required to run the application without exposing a real API key.

Conclusion

You've built a Python CLI application that authenticates with TheCatAPI, sends requests using query parameters, parses JSON responses, handles request and response errors, and supports multiple searches in a single session.
